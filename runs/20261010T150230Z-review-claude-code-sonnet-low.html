   - The view write can't have succeeded in that state, since `chooseSessionView` refuses to send without a confirmed unit. So the case is unreachable today. It would break if someone relaxed that guard.
   - Reproducer: `none — unreachable with the current guard`.

2. **Test gap: no test covers a `load()` that overlaps a view write.**
   - The new `succeededWriteCount` logic for the view field (`viewWritesBeforeThisLoad`, `adoptLoad` skipped for the view) is untested.
   - The existing overlap tests only cover the unit field.
   - A stale load could overwrite a just-confirmed QUICK with FOCUS if that branch regresses.
   - Reproducer: `none — missing test`. A test would hold `getPreferences`, run `chooseSessionView(QUICK)` to completion, release the load with FOCUS, and assert `state.sessionView == QUICK`.

   - The change relies on the backend treating an absent `sessionView` as "unchanged", and on `encodeDefaults = false` for the Json config. Neither is verified here.

   - `a unit write leaves the workout mode off the wire` asserts this using the bare default `Json`, not the production client config, so it doesn't prove the production behaviour.
   - Fix: build the encoder from the real client's Json configuration, or assert against the `MockEngine` request body in an API-level test.
   - Reproducer: `none — need the production Json config`. `grep -rn encodeDefaults shared/src` shows what it actually is.
